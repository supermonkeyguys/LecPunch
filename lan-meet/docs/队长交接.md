# 队长机交接

## 当届队长职责

开会时保持队长机、Docker Desktop 和局域网在线。建议为队长机在路由器中设置 DHCP 静态租约，避免 `LAN_BIND_IP` 变化。

## 新队长接手步骤

1. 安装 Docker Desktop（WSL2 后端）与 Git for Windows（提供 OpenSSL）。
2. 获取此目录的干净副本；不得复制上一届的 `.env`、证书或 Docker 运行目录。
3. 在新队长机生成新的 `MEET_JWT_SECRET`、内部 Jitsi 密码和自签证书。
4. 为新队长机保留稳定 LAN IP，运行：

   ```powershell
   .\scripts\Initialize-LanMeet.ps1 -LanBindIp 192.168.1.50 -LanAllowedCidr 192.168.1.0/24
   .\scripts\Start-LanMeet.ps1
   ```

5. 将新 `MEET_JWT_SECRET` 安全提供给 LecPunch 服务端维护者；服务端更新后再开始会议。
6. 每台参会设备仅信任本届 `certs/meet.crt`，完成双设备验收。
7. 上届队长执行 `scripts/Start-LanMeet.ps1 -Stop` 后，再执行同一 Compose 命令的 `down -v` 清除 Docker 管理的 Prosody 内部证书卷；然后删除其 `.env`、证书、`.runtime` 和 `.upstream` 目录，并撤销旧防火墙规则。

自签证书有效期为 365 天。到期前应在停止会场后重新运行 `Initialize-LanMeet.ps1` 的证书生成步骤，并让每台参会设备替换信任的新证书。

## 密钥轮换

`MEET_JWT_SECRET` 只能用于 Jitsi 准入，绝不能等于或替代 `AUTH_SECRET`。泄露时：停止会议 → 在队长机生成新 `.env` → 服务端同步新值 → 重启 Jitsi 与 API。该轮换不会使成员 LecPunch 登录态失效。

## Windows 说明

- Docker Desktop 首次运行需允许 WSL2 与 Hyper-V 相关提示。
- 防火墙规则创建需要管理员 PowerShell；只放行 Private 网络。
- 运行环境为 **Windows PowerShell 5.1（管理员）或 PowerShell 7（管理员）**；脚本实现仅使用两者共有的 .NET API。`Initialize-LanMeet.ps1` 会在非管理员终端开始前直接拒绝，防止生成一半配置后才因防火墙权限失败。
- `lan-meet/scripts/` 下的 PowerShell 脚本必须以 **UTF-8 with BOM** 保存。Windows PowerShell 5.1 会按本地代码页解析无 BOM 的脚本，中文内容可能导致解析失败；交接时不要以无 BOM 格式重存这些文件。
- 初始化脚本优先使用 Git for Windows 自带的 OpenSSL，并显式传入配套 `openssl.cnf`；不要依赖系统 `openssl` 或 `OPENSSL_CONF` 环境变量。重跑初始化会保留已有的证书，避免让已信任证书的参会设备失效。
- Prosody 的内部 XMPP 证书状态使用 Docker 命名卷而非 Windows 绑定目录，避免 Windows 文件权限导致内部服务无法登录；该卷不对局域网或公网发布端口。
- 自签证书需要在每台参会设备的“受信任的根证书颁发机构”中信任。不要忽略任意未知证书警告。
- Electron 后续只会针对配置中的 LAN 主机与已登记证书指纹放行，不允许通配证书绕过。
